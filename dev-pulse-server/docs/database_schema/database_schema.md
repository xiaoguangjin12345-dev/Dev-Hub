# 数据库设计与实现

## 1.基本配置
- **MySQL建表配置**：存储引擎使用**InnoDB**，支持事务控制与行级锁；字符编码采用`utf8mb4`，支持完整Unicode字符集。
- **MyBatis**：在mapper层编写接口以供业务逻辑层调用，具体的SQL语句编写至接口的注解或mapper对应的xml文件；xml文件内使用`<choose> <when> <if>`等标签，实现语句按需加载，从而实现业务逻辑层面的权限控制、数据隔离与参数化查询。

## 4. 事务控制
- 通过在方法上添加`@Transactional`注解实现。
- 此类方法内的增删改类操作，在该方法全部执行成功后提交；若中途有异常抛出，已经完成的增删改操作全部逆序回滚。
- 通过注解实现的事务具有合并性，一个带事务注解的方法，调用另一个带事务注解的方法，以上过程会**合并为一个整体事务**；整个过程只提交一次事务，中途不会提交被调用方法的操作。
- 事务在本项目中的应用如下：

| 操作 | 涉及事务的表 |
| :---: | :---: |
| **用户注册**<br>（若注册用户角色为**开发人员**）| 用户表 (insert)、开发人员简历表 (insert) |
| **开发人员修改个人信息** | 用户表 (update)、开发人员简历表 (update)、技能标签关联表 (delete, insert) |
| **PMO审批项目立项** | 项目表 (update)、项目审批表 (insert) |
|**项目经理分配任务**|任务表 (insert)、技能标签关联表 (insert)|
|**任务达成双向匹配**|任务表 (update)、任务申请表 (update)|
|**开发人员填写、修改、删除工时日志**|实际工时日志表 (insert / update)、任务表 (update)|
|**项目经理修改任务预估工时**|任务预估工时修改记录表 (insert)、任务表 (update)|
|**开发人员提交任务成果**|任务评审表 (insert)、任务表 (update)|
|**项目经理评审任务**|任务评审表 (update)、任务表 (update)<br>若**评审通过**，还有任务级绩效记录表 (insert)|
|**PMO审批项目结项**|项目表 (update)、项目审批表 (insert)<br>若**审批通过**，还有项目级绩效记录表 (insert) |




> **tips：**<br>以上功能的实现，有较多会伴随**消息通知**的发送，但是消息通知的发送全部设计为异步，因此不属于事务范畴。<br>这里需要格外注意，即使消息通知是异步实现，也需要判断其用到的信息是否为事务提交后的新信息，如果是该情况，需要**先提交事务再发送消息通知**。
