# RabbitMQ应用
## 1. 开发人员填报工时
- 每日下班时间是开发人员工时填报的高峰，通过RabbitMQ接收开发人员的工时填报请求，可减缓较短时间内填报请求全部至数据库的压力，实现**削峰**。
- 通过队列解耦请求与处理后，真正的请求处理执行所在线程，和发起请求的线程是不同的，因此实现异步，该机制称为**异步解耦**。
- 该功能的实现，需要Redis配合存入请求状态数据，以便结果轮询查询。


## 2. 统计分析报表生成
- 和普通业务相比，统计分析涉及的数据聚合运算耗时偏长，线程池占用时间较大。
- 通过RabbitMQ可限制统计分析报表的最大同时处理线程数，具体实现是配置有限的监听器数量并设置每个监听器每次只接收一个请求，这样可以同时实现**削峰**与**监听器的充分利用**。

> 若仅使用信号量，限流功能也可通过纯同步方式或*`@Async`*修饰聚合运算执行模块实现，只不过这些实现的交互效果不会比队列实现友好。

## 3. AI服务实现
- 请求网络大模型API或本地模型的AI生成结果，均需长时间等待，若请求数不加以限制，当请求数增加时，这些线程将长时间大量占用线程池，影响系统其他核心业务的实现。
- 实现原理与目标，和统计分析报表生成相似，具体配置上，监听器数量会**偏少**一些。
> 目前AI服务仅在**辅助项目经理决策任务分配**这一场景试点应用，后续版本还要优化其实现并新增其他AI服务，预留RabbitMQ限流实现，有助于应对后续服务增长。
